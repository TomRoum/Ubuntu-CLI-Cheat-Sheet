CLI in Depth

More detailed explanations are available in Ubuntu's The command line in depth tutorial.

Redirecting Input & Output

Syntax Description
cmd > file Redirect standard output (stdout, file descriptor 1) to a file, replacing its existing contents
cmd >> file Append standard output (stdout, file descriptor 1) to a file
cmd < file Use a file as standard input (stdin, file descriptor 0) for the command
cmd > /dev/null Discard standard output by redirecting it to /dev/null
cmd 2> file Redirect standard error (stderr, file descriptor 2) to a file
cmd > file 2>&1 Redirect both standard output and standard error to the same file
cmd << EOF Feed multiple lines of text to a command as standard input until a line containing the delimiter is reached

Pipes & Command Chaining

Syntax Description
cmd1 | cmd2 Send stdout of cmd1 to stdin of cmd2
cmd1; cmd2 Run commands in sequence regardless of the previous command's exit status
cmd1 && cmd2 Run cmd2 only if cmd1 succeeds with exit status 0
cmd1 || cmd2 Run cmd2 only if cmd1 fails with a non-zero exit status
cmd & Start a command as a background job
{ cmd1; cmd2; } > file Group commands in the current shell and redirect their combined standard output
(cmd1; cmd2) Run the grouped commands in a subshell
cmd1 \ Continue a command onto the next physical line
Subshell: Commands inside ( ... ) run in a separate shell environment, so changes to shell state such as variables or the working directory do not affect the parent shell.

Variables & Environment

Command Description Manual
env List environment variables, or run a command with a modified environment env(1)
echo $VAR Print the current value of the shell variable VAR
VAR=value Set a shell variable in the current shell
export VAR=value Set a shell variable and export it to child processes
unset VAR Remove a shell variable
echo $? Print the exit status of the most recently executed foreground command; 0 conventionally means success
echo $$ Print the process ID (PID) of the current shell
Note: In bash, dash, and zsh, echo is normally provided as a shell builtin.

Shell Expansion

Syntax Description
~ Expands to the current user's home directory, normally represented by $HOME
$VAR or ${VAR} Expand a variable and substitute its current value
$(command) Run a command and substitute its output into the surrounding command
$((expr)) Perform arithmetic expansion; for example, $((5 + 3)) evaluates to 8
{a,b,c} Brace expansion generates separate words, such as {a,b,c} → a b c
{1..10} Brace range expansion generates a sequence, such as {1..5} → 1 2 3 4 5
* Filename glob that matches any sequence of characters
? Filename glob that matches any single character
[abc] Filename glob character class matching one character from the listed set

Useful Command Combinations

These examples combine standard Unix commands into practical troubleshooting and administration workflows.

Command What it does
find . -type f -name "*.log" Find regular files ending in .log below the current directory
grep -Rni "error" /var/log Recursively search log files for "error", ignoring case and showing line numbers
du -h --max-depth=1 | sort -h Show immediate directory sizes sorted from smallest to largest
ps aux | grep <name> Search the process list for a name or pattern
ss -tulpn | grep LISTEN Show TCP and UDP listening sockets and filter for listening entries
cat <file> | wc -l Count lines produced by a file; wc -l <file> is simpler when no pipeline is needed
type <command> Show how the shell resolves a command, including aliases, functions, builtins, or executables
whereis <command> Locate binary, source, and manual-page files associated with a command when available
command -v <command> Ask the current shell how it resolves a command
sed -i 's/old/new/g' <file> Replace text directly in a file; make a backup first when modifying important configuration
tail -f <logfile> Follow new lines appended to a log file in real time
<command> | tee <file> Display command output while simultaneously writing it to a file
<command> | tee -a <file> Display command output while appending it to a file
find . -type f -name "*.sh" -exec chmod +x {} \; Find shell-script files below the current directory and make them executable
find . -type f -name "*.tmp" -delete Find and delete matching temporary files; review the search first when working with important data
Be careful: Commands involving rm, find -delete, chmod, chown, disk devices, and systemctl can make significant system changes. Always verify the target before executing destructive commands.

Commands Not to Run Blindly

This page never runs commands. Treat any command that can delete data, change disks, alter permissions, or gain administrator access as a change request that needs careful review first.

Command pattern Why it is risky Safer habit
rm -rf <path> Forceful recursive deletion can remove a directory tree without asking for confirmation. Inspect the exact path with pwd and ls; prefer a narrow path and an interactive option.
find <path> ... -delete -delete acts on every item matched by the expression, and a broad starting path can have a large effect. Run the same search with -print first and review the list before considering deletion.
dd ... of=/dev/<device> A mistaken output device can overwrite a disk or partition and destroy data. Identify devices with lsblk -f, verify the target twice, and do not guess device names.
any-command > /dev/<device> Shell redirection writes command output directly to a block device, potentially replacing filesystem data. Never redirect output to a disk device unless the target and purpose are explicitly verified.
mkfs ... /dev/<device> or wipefs -a /dev/<device> These can create a filesystem or erase filesystem and partition signatures on the selected device. Unmount the intended device, confirm its identity and backups, and use a documented recovery or installation procedure.
fdisk <device> or parted <device> Partition-table changes can make an entire disk or operating system unavailable. Use a verified device map and backup; treat every write operation as irreversible until proven otherwise.
chmod -R 777 <path> Recursive world-writable permissions can expose or alter files and damage security assumptions. Change only the needed path and permission bits; inspect with ls -ld first.
:(){ :|:& };: A fork bomb repeatedly creates processes until the system runs out of process or other resources. Do not paste shell functions you do not understand; test resource experiments only in an isolated disposable environment.
> <file> A bare output redirect can truncate a file to zero bytes without an external command. Confirm the filename and use a backup before redirecting output into an existing file.
history | sh This can feed previously recorded commands back into a shell and repeat unintended changes. Review history entries individually; never pipe an entire history into a shell.
crontab -r Removes the current user's crontab, deleting scheduled jobs without a normal confirmation prompt. Back up with crontab -l before editing and use crontab -e for changes.
sudo apt purge <package> or sudo apt autoremove Package removal can remove configuration, applications, or dependencies you still need. Read APT's proposed changes and confirm the package list before accepting.
^old^new In shells that support history substitution, this edits and immediately reruns a previous command. Print and inspect the expanded command before rerunning it; prefer a fresh command when unsure.
mv <file> /dev/null Moving a file onto the special /dev/null path can replace that device node and break programs that rely on it. Use rm only after confirming the file, and never treat special paths as ordinary folders.
curl <URL> | bash or wget -O- <URL> | sh This downloads text from the network and immediately hands it to a shell with whatever privileges are present. Download, inspect, verify the source and checksum, and run scripts only in a controlled environment.
gunzip <untrusted-file>.gz Untrusted compressed input can expand unexpectedly, consume disk space, or contain files with surprising names and paths. Inspect archive contents and provenance first; extract into a temporary location with sufficient controls.
sudo apt purge python<version>-minimal Removing a Python package used by system tools can break desktop or administrative components. Check package reverse dependencies and avoid removing distribution-managed runtimes without a recovery plan.
sudo systemctl disable <service> or sudo userdel <user> Administrative service and account changes can interrupt boot, networking, access, or other users' work. Check current status, dependencies, recovery access, and the exact target before changing it.
Stop and verify: A command shown here is an explanation, not a recommendation to run it. When unsure, consult the command's manual and Ubuntu documentation before using sudo or touching a system path or disk device.
